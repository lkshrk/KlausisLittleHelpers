# Contributing

Lua 5.1 only, ASCII only in code, comments, strings and docs. Almost no comments: one short line at most, only for a non-obvious why. See [docs/](docs/) for the architecture.

## Setup

Needs `bash`, `lua5.1`, `luac5.1`, `git`, `rsync`. Optional: `luacheck`, `lefthook`, `gitleaks`, `shellcheck`, `yq`, `actionlint`, `python3`.

```sh
lefthook install          # once per clone
scripts/ui-source.sh update   # Blizzard UI source and the WoW API annotations for the editor
```

`.luarc.json` points the Lua language server (LuaLS) at `~/.local/share/wow/vscode-wow-api/Annotations`, so WoW globals resolve in the editor.

Pre-commit checks staged files (gitleaks, luac, luacheck, tests, TOC, shellcheck, YAML, actionlint). Pre-push runs `scripts/check.sh`. Do not skip hooks with `--no-verify`.

## Check and test

```sh
scripts/check.sh   # luac, TOC coverage, tests, luacheck, ASCII check
scripts/test.sh    # only the tests in .tools/tests
```

Run `scripts/check.sh` before committing. CI runs it too, plus shellcheck, actionlint and gitleaks.

## Try it in game

```sh
scripts/sync.sh retail|forever|all [--dry-run]   # copy into the AddOns folder, then /reload
scripts/errors.sh [retail|forever] [pattern] [--all-sessions]   # read !BugGrabber errors
```

`WOW_DIR` overrides the game folder. Sync only the flavor the change targets and preview with `--dry-run` first. Never commit SavedVariables, WTF data, logs or packaged zips.

## Generated data

`Data/Writs.lua`, `Data/WaylaidCrates.lua` and `Data/TaxiPaths.lua` are generated by `scripts/writ-data.py` and `scripts/taxi-data.py`. Change the TSV or the generator and run it again; never edit them by hand. `scripts/writ-data.py <questie-db-dir> <tooltip-cache-dir> [--fetch] [--build 1.60.1]` takes the game build for the generated headers; it defaults to the current Forever build.

## Release

```sh
scripts/release.sh patch|minor|major   # tags X.Y.Z (no v prefix) and pushes branch and tag
```

The release workflow packages the tag with the BigWigs packager once CI passes on that commit. The TOC keeps `## Version: @project-version@`; the packager fills it from the tag, and `scripts/sync.sh` writes the `git describe` version (or `dev-<sha>` before the first tag, `-dirty` with uncommitted changes) into the copied TOC.

The CurseForge project description is a short permanent text that links to the README; CurseForge has no API to update it, so it is not kept in sync. Per-release changes reach CurseForge through the changelog the packager uploads with each file. Wago reads the README on its own.
